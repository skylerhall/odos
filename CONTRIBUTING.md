# Contributing to ODOS

Thanks for helping. Bug reports, fixes and new ideas are all welcome.

## Reporting a bug

Open an issue with what you did, what you expected, what happened, and your phone and Android
version. A screenshot helps a lot. Please leave out your exact location unless the bug depends on it.

## Making a change

1. Fork the repo and follow [Build your own](README.md#build-your-own) to get it running.
2. Make your change on a branch.
3. Run the checks:
   ```bash
   npm test
   npm run typecheck
   npm run lint
   ```
4. Open a pull request saying what changed and how you tested it (on a phone, an emulator, or
   Sim mode).

For a big change, open an issue first so we can agree on the approach before you put in the work.

## How the code is organized

- `src/core/` is pure TypeScript with no React Native imports, so it can be unit-tested with
  `npm test`. Keep it that way: logic goes here, with tests in `tests/`.
- `src/services/` does network and device I/O.
- `src/state/useOdos.ts` owns app state and wires core and services together.
- `src/ui/` holds components and sheets. Touch targets are at least 56 px and every control has a
  screen-reader label.
- Sheets that load data are mounted only while open and load through `src/ui/useAsync.ts`.
- Tunable rules live in `src/config.ts`.
- `ios/` and `android/` are generated by `npx expo prebuild`. Don't commit them; configure native
  behavior in `app.json` and config plugins instead.
- Add dependencies with `npx expo install <package>` so versions match the Expo SDK.

## Secrets

Never commit API tokens, `.env`, or signing keys. The Mapbox token goes in `.env` locally and in a
repository secret for CI.
